## 1. 设计理念

### 1.1 核心命题

金融 AI 智能体不是"对话框里的聪明人"，而是**能理解目标、拆解任务、调用工具、连接数据、持续执行并完成闭环的"数字员工"**。

### 1.2 三大设计原则

| 原则 | 来源 | 内涵 |
|------|------|------|
| **Skills + Connectors + Subagents** | Anthropic | 标准化三层模块化架构，每个 Agent = 技能指令 + 数据连接 + 子智能体 |
| **芯—云—模—智 全栈** | 阿里云点金 | 从芯片到应用的全栈可控，确保性能、安全、合规 |
| **Human-in-the-Loop** | 两者共识 | 智能体不执行交易、不批准入驻、不过账——所有输出由专业人员复核 |

### 1.3 设计目标

- **准确性**：金融场景对错误的零容忍，通过可信数据源 + 自验证机制保证
- **合规性**：全链路审计追溯，每一步决策可解释、可回溯
- **安全性**：沙箱隔离执行，细粒度权限控制，凭证隔离
- **可扩展性**：技能和市场数据连接器可插拔，支持私有化部署

## 3. Agent 体系设计

### 3.1 Agent 分类体系

综合 Anthropic 10 Agent 模板 + 阿里云点金 10 大岗位角色，设计 12 个核心 Agent：

| # | Agent 名称 | 业务领域 | 核心职责 | 参考来源 |
|---|-----------|---------|---------|---------|
| 1 | **Investment Researcher** | 投研分析 | 行业研究、公司深度研报、竞争格局、投资想法生成 | Anthropic Market Researcher + 点金投研分析师 |
| 2 | **Financial Modeler** | 财务建模 | DCF/LBO/三表模型构建与更新、敏感性分析 | Anthropic Model Builder |
| 3 | **Earnings Analyst** | 财报分析 | 财报解读、电话会分析、盈利预测更新、异动检测 | Anthropic Earnings Reviewer |
| 4 | **Pitch Builder** | 投行覆盖 | 可比分析→路演材料端到端生成 | Anthropic Pitch Agent |
| 5 | **Wealth Advisor** | 财富管理 | 客户评审、财务规划、组合再平衡、税务优化 | Anthropic (wealth-management) + 点金投顾 |
| 6 | **Risk Controller** | 风控 | 信贷进件识别、风险评估、额度建议、预警监控 | 点金信贷风控 |
| 7 | **Insurance Processor** | 保险 | 智能核保核赔、理赔审核、文档解析 | 点金保险展业 |
| 8 | **Compliance Officer** | 合规 | KYC/AML筛查、制裁名单检查、监管报告生成 | Anthropic KYC Screener + 点金合规 |
| 9 | **Fund Operator** | 基金运营 | 总账对账、NAV核对、月末关账、报表审计 | Anthropic GL Reconciler + Month-End Closer |
| 10 | **Deal Advisor** | 交易执行 | 买方名单、尽调清单、IC备忘录、并购模型 | Anthropic (investment-banking) |
| 11 | **Market Monitor** | 市场监控 | 实时行情监控、异常检测、事件驱动预警 | 综合设计 |
| 12 | **Commander** | 编排调度 | 任务理解→Agent分配→结果整合→报告生成 | 点金 Harness + Anthropic Orchestrator |

### 3.2 Agent 标准结构

每个 Agent 遵循 Anthropic 的三层模块化标准：

```
agent-name/
├── AGENT.md              # 系统提示词（角色定义、能力边界、行为约束）
├── skills/               # 技能文件（Markdown 领域知识 + 分步方法）
│   ├── core/             #   核心分析技能
│   └── domain/           #   领域专用技能
├── connectors/           # 数据连接器配置
│   └── .mcp.json         #   MCP 服务器列表
└── subagents/            # 子智能体定义（深度1）
    └── *.md              #   子智能体的系统提示词
```

### 3.3 Agent 生命周期

```
用户输入 → Commander 理解意图 → 任务拆解 → Agent 分配
    → Agent 加载技能 + 连接数据源 → 执行(Plan→Act→Observe→Iterate)
    → 子 Agent 协作（必要时）→ 自验证 → 输出草稿
    → 人工复核 → 最终输出 → 审计日志归档
```

### 5.3 连接器治理

| 治理维度 | 策略 |
|---------|------|
| **访问控制** | 按 Agent 角色授予最小必要数据权限 |
| **数据脱敏** | PII/敏感字段自动脱敏后再入上下文 |
| **审计日志** | 每次数据访问记录：who/when/what/source |
| **缓存策略** | 热点数据缓存(5min TTL)，减少外部调用 |
| **熔断降级** | 外部数据源超时/不可用时降级为本地缓存 |

### 6.2 编排策略

| 策略 | 适用场景 | 模式 |
|------|---------|------|
| **并行扇出** | 多维度独立分析（如同时分析基本面+技术面+消息面） | 1→N→1 |
| **串行流水线** | 有依赖关系的任务链（如尽调→估值→备忘录） | 1→2→3 |
| **辩论模式** | 高重要度决策（多头/空头辩论→风控裁决） | 1→N辩论→1 |
| **条件路由** | 基于规则引擎的分支（合规检查→通过/驳回） | 1→分支→各自处理 |
| **循环迭代** | 需多轮修正的任务（模型审计→修复→再审计） | Loop until pass |

### 6.3 上下文管理

参考 Anthropic 的上下文工程实践：

| 技术 | 说明 |
|------|------|
| **Compaction（压缩）** | 上下文接近窗口上限时自动压缩历史，传递摘要到新窗口 |
| **Agentic Memory** | 智能体在运行中做结构化笔记，后续运行可重读 |
| **Progressive Disclosure** | 工具设计支持分页/过滤参数，避免上下文过载 |
| **File-based State** | 通过 `task_plan.md` / `findings.md` / `progress.md` 保持跨 Agent 状态 |

## 7. 安全合规架构

### 7.1 四道防线（参考点金 + 强化）

```
第一道防线 — 输入安全
├── 可信数据源直连，禁止使用公开未审核数据
├── 输入内容过滤：防止提示注入、越权指令
├── 数据脱敏：PII/账户信息自动脱敏
└── 来源验证：数据源可信度评分

第二道防线 — 执行安全
├── 金融级弹性沙箱：每个 Agent 独立隔离环境
├── 沙箱启动 < 100ms，执行完毕自动销毁
├── 网络隔离：沙箱仅允许访问授权 MCP 端点
├── 资源限制：CPU/内存/时间配额硬限制
└── 写入权限：仅特定叶子 Agent 拥有写入能力

第三道防线 — 过程安全
├── 全链路审计日志：每次工具调用、每次决策记录
├── 操作可追溯：who/when/what/why 完整记录
├── 凭证隔离：不同 Agent 使用不同凭证
├── 权限粒度：工具级别的细粒度访问控制
└── 异常检测：行为模式异常实时告警

第四道防线 — 输出安全
├── 输出内容合规审查：敏感信息泄露检查
├── 人工复核门禁：关键输出需人工确认
├── 输出留痕：所有输出带版本号和生成时间
├── 责任溯源：可追溯到具体 Agent + 输入数据
└── 合规报告：自动生成监管报送数据
```

### 7.2 合规对齐

| 监管框架 | 适用范围 | 合规要点 |
|---------|---------|---------|
| **中国监管** | 境内业务 | 数据本地化、个人金融信息保护、算法备案、金融科技监管沙盒 |
| **Basel III** | 银行 | 资本充足率、流动性风险、操作风险 |
| **IFRS 17/9** | 保险/银行 | 预期信用损失、保险合同计量 |
| **GDPR** | 欧盟客户 | 数据主体权利、跨境传输限制 |
| **SEC/FINRA** | 美国业务 | 记录保存、最佳执行、公平披露 |

### 9.2 关键架构决策

| 决策 | 选择 | 理由 |
|------|------|------|
| **Agent 定义格式** | Markdown + YAML | 人机可读，Git 可管理，无构建步骤 |
| **数据连接协议** | MCP (Model Context Protocol) | Anthropic 推行的开放标准，生态丰富 |
| **Agent 通信** | Handoff Protocol + 共享文件 | 解耦 Agent 间通信，支持异步 |
| **上下文管理** | Compaction + Agentic Memory | 突破 LLM 上下文窗口限制 |
| **沙箱隔离** | 容器级隔离 + 网络策略 | 安全可控，性能开销低 |
| **模型路由** | 按任务复杂度分级调用 | 成本优化，简单任务用小模型 |
