# 弈金研究判断工作台设计

日期：2026-09-12

## 1. 设计结论

弈金下一阶段不应继续围绕“生成一份更好看的报告”迭代，而应转向“帮助投研人员建立、验证、更新和复盘投资判断”。

新的产品内核：

> 普通 AI 生成回答；弈金沉淀判断。

报告仍然保留，但它只是研究过程的导出物。真正的核心对象应是公司研究档案、证据账本、关键假设、价值驱动树、判断图谱、反方挑战和跟踪事件。

## 2. 目标用户

首批目标用户不是泛金融从业者，也不是个人投资者，而是：

- A 股上市公司买方研究员
- 卖方分析师和研究助理
- 基金、券商、私募、中小机构投研团队
- 需要快速覆盖公司、跟踪公告、形成观点和复核底稿的专业用户

首版暂不服务：

- 普通散户的买卖建议
- 自动交易用户
- 纯财富管理顾问
- 理赔、信贷、反欺诈等非证券投研场景

## 3. 金融投研工作的本质

投研人员的专业工作不是写报告，而是在信息不完整、未来不确定、责任明确的环境下，持续形成和更新判断。

真实工作循环是：

```text
信息收集
  → 重要性判断
  → 公司理解
  → 核心假设
  → 证据验证
  → 投资观点
  → 反方挑战
  → 新信息更新
  → 复盘修正
```

其中最有价值的能力不是文字表达，而是：

- 抓住影响公司价值的主要矛盾
- 判断哪些资料可信、哪些只是噪声
- 建立商业模式、财务指标和估值之间的因果关系
- 发现市场共识之外的非共识判断
- 识别什么事实会证明自己错了
- 在复盘时解释当时为什么这么判断

因此产品要帮助用户完成的不是“写得更快”，而是“判断更稳、证据更清楚、复盘更容易”。

## 4. 当前流程的问题

当前实现的主流程是：

```text
上传材料
  → Commander 拆题
  → Specialist 并行生成文本
  → Report Synthesizer 汇总
  → 展示报告和搜索引用
```

这个流程能完成演示，但在专业投研场景里有四个根本问题。

### 4.1 研究对象不稳定

系统现在把一次分析请求当成一个 Task，而不是把公司当成持续研究对象。结果是每次提问都像重新开始，旧结论、旧证据、旧假设难以沉淀。

### 4.2 证据没有成为判断资产

已上传材料可以解析成页码级证据，但证据还没有绑定到具体判断、假设、风险和结论上。用户无法回答“这个结论为什么成立、来自哪几条证据、有没有反证”。

### 4.3 Agent 输出仍然偏文本

Specialist 现在主要输出 Markdown 报告。专业工作需要的是结构化底稿：观点、证据、关键数字、假设、反证、缺口、置信度和复核状态。

### 4.4 报告中心化过强

报告是最后产物，但用户真正需要持续使用的是研究驾驶舱：当前判断是什么、最大不确定性是什么、下一步要验证什么、新事件是否改变原判断。

## 5. 新产品范式：公司研究驾驶舱

每个公司应有一个持续存在的研究档案，而不是一堆孤立任务。

```text
ResearchSubject 公司研究对象
  ├─ 当前判断
  ├─ 核心假设
  ├─ 价值驱动树
  ├─ 证据账本
  ├─ 判断图谱
  ├─ 反方观点
  ├─ 风险清单
  ├─ 待验证问题
  ├─ 跟踪事件
  └─ 报告版本
```

第一屏应回答五个问题：

1. 当前判断是什么？
2. 判断依据是什么？
3. 最大不确定性是什么？
4. 哪些证据支持或反对？
5. 下一步该验证什么？

## 6. 核心工作流

### 6.1 首次覆盖

用户上传年报、公告或研究材料后，系统不直接生成长报告，而是建立公司认知底座：

```text
识别公司
  → 抽取商业模式
  → 抽取收入/利润/现金流结构
  → 识别核心变量
  → 生成初始假设
  → 生成待核验问题
  → 给出初始研究摘要
```

用户看到的是一张公司研究地图，而不是一篇普通总结。

### 6.2 提出研究问题

用户问“怎么看宁德时代”时，系统不应直接输出大报告，而应先形成判断框架：

```text
当前判断：中性偏积极
置信度：中
证据强度：中
主要依据：储能增长、成本改善、份额稳定
主要反证：价格竞争、海外政策、回款质量
下一步验证：储能订单、海外产能利用率、毛利率拆分
```

用户可以继续要求“生成正式报告”，但正式报告应基于这些结构化对象生成。

### 6.3 新事件跟踪

用户上传新公告或系统检索到新事件后，系统不应重新生成完整报告，而应回答：

```text
这条新信息影响了哪个假设？
增强还是削弱原判断？
是否改变风险等级？
是否需要更新目标价、评级或观察结论？
是否需要提示用户复核？
```

### 6.4 反方挑战

每个正向观点必须生成反方挑战：

```text
如果这个判断错了，最可能错在哪里？
哪些证据支持相反结论？
市场为什么可能不同意？
风控或投委会会追问什么？
需要补充哪些数据才能提高置信度？
```

反方挑战不是附加功能，而是金融研究质量控制的一部分。

## 7. 核心对象设计

### 7.1 ResearchSubject

研究对象，通常是一家 A 股上市公司。

关键字段：

- 公司名称
- 股票代码
- 行业
- 研究状态
- 当前判断
- 判断更新时间

### 7.2 EvidenceItem

证据项，来自 PDF、公告、网页或后续数据源。

关键字段：

- 来源类型
- 来源名称
- 页码或 URL
- 文本片段
- 提取时间
- 可信等级
- 关联公司

### 7.3 Claim

判断图谱中的单个判断。

关键字段：

- 判断内容
- 判断方向：正面 / 中性 / 负面
- 置信度：高 / 中 / 低
- 证据强度：强 / 中 / 弱
- 支持证据
- 反向证据
- 影响变量
- 状态：待核验 / 已支持 / 被削弱 / 被推翻

### 7.4 Assumption

影响判断成立的核心假设。

关键字段：

- 假设内容
- 所属维度：收入、利润率、现金流、估值、政策、竞争格局
- 支持证据
- 反证
- 触发条件
- 失效条件

### 7.5 Driver

价值驱动变量。

关键字段：

- 变量名称
- 方向
- 影响路径
- 相关指标
- 当前状态
- 更新频率

### 7.6 Challenge

反方挑战。

关键字段：

- 被挑战的判断
- 反方问题
- 反向证据
- 风险等级
- 建议验证动作

### 7.7 DecisionMemo

决策备忘录，比报告更贴近日常投研协作。

关键字段：

- 当前结论
- 关键依据
- 最大不确定性
- 建议动作
- 待复核项
- 生成时间

### 7.8 ReportVersion

正式报告版本。

关键字段：

- 报告内容
- 引用清单
- 生成时间
- 复核状态
- 复核人
- 导出状态

## 8. Agent 角色重排

保留 Commander + Specialist，但重新定义职责。

### 8.1 Research Planner

替代当前“直接拆 Agent 任务”的 Commander 第一阶段。

职责：

- 识别研究对象和研究意图
- 判断是首次覆盖、财报点评、事件跟踪还是风险复核
- 生成研究问题树
- 生成所需证据清单
- 判断材料缺口

### 8.2 Evidence Analyst

职责：

- 从材料中抽取事实、数字、管理层表述和风险披露
- 将证据挂接到公司、指标、假设或判断
- 标记证据质量

### 8.3 Driver Analyst

职责：

- 建立价值驱动树
- 识别影响公司价值的核心变量
- 判断变量之间的因果路径

### 8.4 Specialist Analysts

现有行业、基本面、消息面、风险等 Specialist 继续保留，但输出必须从 Markdown 改为结构化底稿：

```text
观点
证据
关键数字
假设
反证
置信度
待核验项
```

### 8.5 Challenge Agent

职责：

- 主动反驳核心判断
- 找出薄弱证据
- 生成投委会式追问
- 提醒用户哪些结论不能直接用于正式报告

### 8.6 Report Synthesizer

职责从“合成多 Agent 文本”降级为“根据已核验底稿生成可导出的报告”。

## 9. 第一阶段 MVP 范围

第一阶段不要一次做完完整系统。最小可用闭环是：

```text
上传材料
  → 识别研究对象
  → 生成证据账本
  → 生成核心假设
  → 生成初始判断
  → 生成反方挑战
  → 生成决策备忘录
```

第一阶段必须能让用户感受到：

- 不是只总结材料，而是提炼关键变量
- 不是只给结论，而是给证据和反证
- 不是只生成报告，而是告诉用户下一步该验证什么

第一阶段不做：

- 自动交易
- 个性化买卖建议
- 复杂估值模型
- 扫描件 OCR
- 全量结构化财务数据库
- 多机构协同审批

## 10. 页面调整建议

### 10.1 Dashboard

从“Commander 输入框”改为“研究工作台入口”。

主要入口：

- 新建公司研究
- 上传研究材料
- 查看最近研究对象
- 查看待复核判断

### 10.2 公司研究驾驶舱

新核心页面。

模块：

- 当前判断卡
- 核心假设列表
- 价值驱动树
- 证据账本
- 反方挑战
- 待验证问题
- 最近事件影响
- 报告版本

### 10.3 材料页

不只显示文件列表，还应显示：

- 已抽取证据数量
- 涉及指标
- 涉及假设
- 未能解析或待人工确认的片段

### 10.4 报告页

报告页仍然存在，但应显示：

- AI 草稿 / 已复核
- 关键判断引用覆盖率
- 待核验项
- 反方挑战摘要
- 导出门禁

## 11. 成功指标

产品不应只用“生成报告耗时”衡量，而应增加判断质量指标：

- 材料证据抽取成功率
- 关键判断引用覆盖率
- 关键数字可追溯率
- 待核验项召回率
- 反方挑战有效率
- 用户修改判断的比例
- 新事件触发判断更新的准确率
- 研究对象复用率

## 12. 实施顺序

推荐顺序：

1. 新增 ResearchSubject，建立公司级研究对象。
2. 将现有 DocumentEvidence 关联到 ResearchSubject。
3. 新增 Claim、Assumption、Challenge、DecisionMemo 基础模型。
4. 上传材料后生成证据账本和初始假设。
5. Commander 改为先生成 ResearchPlan，再分派 Specialist。
6. Specialist 输出结构化底稿，不再直接作为最终报告。
7. 新增 Challenge Agent，对核心判断做反方挑战。
8. 前端新增公司研究驾驶舱。
9. 报告生成改为从判断、证据、假设、挑战和备忘录生成。
10. 加入复核状态和导出门禁。

## 13. 关键取舍

### 13.1 不把 Agent 数量作为卖点

更多 Agent 容易制造复杂度，但不一定提升研究质量。下一阶段应先把少量 Agent 的输出结构化、可核验、可复用。

### 13.2 不把报告作为中心

报告是交付物，判断才是资产。产品应优先优化判断建立和更新过程。

### 13.3 不急于接全量数据源

结构化财务数据重要，但第一阶段更关键的是建立证据、假设和判断的对象模型。没有这个模型，接入数据源也只是让报告多一些数字。

### 13.4 不隐藏不确定性

普通 AI 倾向给完整答案。弈金应明确展示不确定性、证据缺口和反方挑战，这是专业金融工作的重要组成。

## 14. 定位表达

推荐对外表达：

> 弈金是面向 A 股投研人员的研究判断工作台。它把上传材料、公开信息和历史研究沉淀为证据账本，帮助研究员建立核心假设、形成投资判断、接受反方挑战，并持续跟踪新事件对原判断的影响。

更短版本：

> 普通 AI 帮你写报告，弈金帮你维护判断。
