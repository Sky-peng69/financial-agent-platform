# Decision Log

## LOCKED

- 弈金不再以“报告生成器”或“上市公司研究工作台”为产品中心。
- 核心定位改为“企业金融动态尽调与决策智能体”。
- 首要用户为银行公司金融、普惠金融和风险管理人员；上市公司研究能力保留为企业分析能力的一部分。
- 尽调备忘录和报告是导出物，企业金融状态、证据、风险判断、融资需求和行动建议才是产品核心。
- 不继续以增加 Agent 数量作为主要差异化。
- Agent 按金融流程职责划分：事实核验、企业画像、行业尽调、风险与信用、金融匹配、治理与审计。
- 第一阶段只实现企业金融尽调智能体，不自动授信、调额、支付、交易或对外发送金融结论。
- 事件影响分析必须保留历史判断，不自动覆盖结果，新增结论进入人工复核。
- 当前第一阶段围绕 `ResearchSubject / Claim / Assumption / Evidence / Challenge / DecisionMemo` 落地。
- 分析可以使用上传材料，但产品不在前端刻意标注和暴露“使用了哪些材料片段”的内部处理过程。
- 公司研究驾驶舱内的 AI 分析结果应沉淀为结构化判断资产，而不是只生成一份 Markdown 报告。
- 判断和假设必须保留可展开的证据引用与核验状态；主界面保持简洁，证据片段只在用户主动展开时显示。
- 判断和假设必须允许人工确认、驳回和编辑；复核动作是判断资产进入正式研究流程的第一层门槛。
- 判断和假设的确认、驳回、编辑必须留下不可变历史记录，支持投研复核追溯。

## ASSUMPTION

- 首版公司研究驾驶舱允许用户手工录入判断、假设、挑战和备忘录。
- 首版自动生成判断资产先使用研究对象下的页码级材料文本，不额外引入结构化财务数据库。
- 前端保持克制、密集、可扫描的投研工作台风格。
- 首版用 `evidence_ids` 字段保存判断/假设到 `DocumentEvidence` 的引用；后续需要更完整审计时再升级为独立引用表。
- 当前复核状态直接保存在判断/假设表中；资产级审计历史保存在 `ResearchAssetAudit`。
- 本地确定性 stub 只用于验证 API、数据库、审计和权限链路，不能作为真实模型输出质量的证据。
- Codex 与 Claude Code 改为串行接力：Codex 完成功能/文档交接后，Claude Code 独占后端测试与修复车道，之后 Codex 再做最终全链路验收；不同时验证同一闭环。
- Claude Code Round 1 已完成并合并到 `main`；后端测试车道现已存在，后续不为重复验证持续运行两个 agent。

## OPEN

- 企业金融对象与旧 ResearchSubject 持久化对象的长期命名迁移时机。
- 事件、行动建议与现有 ResearchClaim/ResearchAssumption 的关系是否需要独立引用表。
- 授权税务、电商、物流、银行流水和设备数据连接器的优先级。
- 自动生成判断资产的真实模型输出质量、提示词稳定性和核验流程。
- 开发环境当前 DeepSeek API Key 返回 401；在有效凭证恢复前，不将真实模型生成质量标记为已验证，也不擅自修改或撤销外部密钥。
- 企业事件与旧 Task/Commander 流程如何深度融合。

## REJECTED

- 暂不做自动交易。
- 暂不做个人化买卖建议。
- 暂不以扩展更多 Agent 作为下一阶段重点。
- 暂不做全量结构化财务数据库接入。
