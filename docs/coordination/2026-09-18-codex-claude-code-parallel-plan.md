## 每次交接格式

双方交接必须包含：

1. 本轮目标和完成情况。
2. 修改文件清单。
3. API/schema/数据库变更。
4. 已执行的验证命令及结果。
5. 未解决问题和风险等级。
6. 对另一方的明确依赖。
7. 是否允许合并；默认不允许，除非验证结果完整。

## 最终验收标准

- 新用户可在本地启动并打开前端。
- 一份企业 PDF 能生成页码级证据。
- 生成结果至少包含一个带证据或明确“待核验”的行动建议。
- 新事件能返回受影响判断、受影响建议和证据缺口。
- 融资需求能落库，保留金额原文、证据关联和人工复核状态。
- 影响结果只有在人工操作后才转为待复核动作。
- 确认/驳回能留下前后内容、状态、备注、用户和时间。
- 跨用户访问返回 404/403，不泄露资源存在性。
- 原有报告和研究工作区接口通过非回归测试。
- 前端构建、后端测试和完整演示回放全部通过后，才进行一次线上部署。
