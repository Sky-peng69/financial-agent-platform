# 弈金项目 Codex × Claude Code 协同计划

## 协同目标

让两个 Agent 并行推进“企业金融尽调与决策智能体”，但不同时修改同一批文件，不把未经验证的结果直接部署到线上。

当前约束：

- Codex 负责产品主线、架构决策、体验设计、验收和最终整合。
- Claude Code 负责后端工程、运行环境、测试和代码级修复。
- 两边使用隔离 worktree 或分支；禁止直接共享同一个未提交工作区。
- 线上部署只在全部策划、实现和本地验证完成后执行一次。

## 文件所有权

| Agent | 主要负责 | 默认不修改 |
|---|---|---|
| Codex | `docs/**`、`frontend/**`、产品方案、竞赛材料、验收标准、最终整合 | `backend/**`，除非双方明确交接 |
| Claude Code | `backend/**`、后端测试、数据库运行和 API 验证 | `frontend/**`、`docs/**` |

如果必须跨越文件边界，先在交接记录中说明原因、影响文件和回滚方式。

## 第一轮并行任务

### Codex：产品与体验主线

1. 完成产品定位 2.0、竞赛策划书叙事和金融机构落地路线。
2. 固化核心演示场景：
   `企业材料 → 企业画像 → 风险判断 → 录入经营事件 → 影响分析 → 新行动建议 → 人工复核 → 审计回放`。
3. 完成前端尽调工作台：材料入口、行动建议、事件影响预览、复核状态、报告导出定位。
4. 建立评测集说明：企业样本、固定问题、证据追溯率、行动建议可执行性、人工修改率。
5. 不改变后端 API 契约；发现后端问题时写入交接清单，不直接改后端。

### Claude Code：后端工程主线

1. 在独立 worktree 中运行后端，补齐项目 requirements 和本地数据库启动验证。
2. 为以下链路编写 API/服务测试：
   - 创建企业研究对象。
   - 上传 PDF 并生成证据片段。
   - 生成结构化行动建议。
   - 创建企业事件。
   - 生成事件影响预览。
   - 将影响结果转为待复核行动建议。
   - 确认/驳回并检查审计记录。
3. 检查权限边界：用户不能读取其他用户的企业、证据、事件、建议或审计历史。
4. 检查旧接口非回归：原有 claims、assumptions、reports、workspace 不因新增字段失败。
5. 修复后端发现的问题，但不扩展到自动授信、自动调额、支付、交易或外部生产系统接入。

## 第二轮并行任务

只有第一轮接口契约稳定后才开始：

- Codex：根据 Claude Code 的 API 测试结果，完善前端错误状态、空状态、加载状态和演示数据。
- Claude Code：完善事件影响结果的持久化/回放、任务失败重试、审计查询和数据库迁移兼容。

两边都完成后再进入整合，不在第二轮中途部署。


## 每次交接格式

双方交接必须包含：

1. 本轮目标和完成情况。
2. 修改文件清单。
3. API/schema/数据库变更。
4. 已执行的验证命令及结果。
5. 未解决问题和风险等级。
6. 对另一方的明确依赖。
7. 是否允许合并；默认不允许，除非验证结果完整。

## 最终验收标准

- 新用户可在本地启动并打开前端。
- 一份企业 PDF 能生成页码级证据。
- 生成结果至少包含一个带证据或明确“待核验”的行动建议。
- 新事件能返回受影响判断、受影响建议和证据缺口。
- 影响结果只有在人工操作后才转为待复核动作。
- 确认/驳回能留下前后内容、状态、备注、用户和时间。
- 跨用户访问返回 404/403，不泄露资源存在性。
- 原有报告和研究工作区接口通过非回归测试。
- 前端构建、后端测试和完整演示回放全部通过后，才进行一次线上部署。
