# 弈金：面向银行投研场景的可追溯上市公司智能研究工作台

## 项目摘要

弈金是一款面向工商银行内部研究、投研和资产管理人员的上市公司智能研究工作台。项目以数字金融为主参赛方向，围绕“上传材料—智能拆解—多角色分析—来源核验—人工复核—报告归档”的完整研究闭环，解决金融研究中资料分散、任务串行、专业方法难以复用、研究结论难以核验和知识难以沉淀等问题。

在上市公司研究场景中，研究人员需要同时处理年报、公告、行业资料、政策信息、新闻和财务数据，并从行业、基本面、消息面、估值和风险等多个角度形成判断。传统方式高度依赖个人经验，资料搜集与整理耗时，研究过程难以复用；通用对话式人工智能又容易出现来源不清、数字口径不一致、过程不可追溯和责任边界不清的问题。

弈金采用 Commander + Specialist 的任务编排方式。Commander 负责理解研究目标、生成结构化任务图和安排依赖关系；行业、基本面、消息面、估值、风险等 Specialist 按照专业分工并行或按依赖执行；Search Provider 保存公开来源；共享质量协议核验引用、数字、计算、完整性和风险；报告合成师最终形成带来源、生成时间、风险提示和人工复核状态的研究报告草稿。

项目不是重新训练一个通用金融大模型，而是建设金融模型、知识、材料和专业分工之间的应用层。工商银行公开信息显示，其已经围绕“领航AI+”行动、“工银智涌”金融大模型、企业知识工程、智能体协同和智能投研助手持续建设。弈金可以作为研究业务应用层的候选方案，与大型金融机构的模型底座和知识工程形成适配关系，而不是替代既有底座。

项目当前已经具备 Web 工作台、Agent 注册与编排、SSE 实时进度、公开网页检索、引用展示、任务历史和 Docker 部署等 MVP 基础。后续将围绕结构化 DAG、公开金融数据接入、质量评测、权限隔离和机构试点逐步推进。普通投资爱好者可以使用弈金进行公开资料研究辅助，但系统不提供个性化买卖指令，不自动交易，正式报告必须经过人工复核。

## 一 项目概况与参赛定位

### 1.1 项目名称

项目名称：弈金。

项目定位：面向银行投研场景的可追溯上市公司智能研究工作台。

主参赛方向：数字金融。

关联方向：金融安全、开放创新、智慧银行。

### 1.2 目标用户

主要用户为工商银行内部研究、投研和资产管理人员，核心需求是提高上市公司、行业和企业材料研究的效率与可核验性。

普通投资爱好者是次级用户，使用范围限定为公开资料研究辅助，包括公司资料整理、行业信息理解、风险提示和来源查看。系统不根据个人资产、风险偏好和收益目标生成个性化买卖建议，也不代替用户作出投资决策。

科技金融人员、证券公司和基金公司投研机构是扩展用户。未来可以将上市公司研究能力延伸到科技型企业尽调、行业研究、企业客户分析和机构研究协作等场景。

### 1.3 核心场景

弈金的第一个核心场景是上市公司深度研究闭环。

用户上传上市公司年报、公告或其他研究材料，输入“综合评估某公司的行业地位、基本面、估值与风险”等研究问题。系统自动生成任务图，分派行业、基本面、消息面、估值和风险 Specialist，并行完成资料提取、公开信息补充和专业分析，最后合成研究报告草稿。

这个场景同时体现了：

- 金融研究的真实业务链条；
- 多 Agent 协作的必要性；
- PDF 材料和公开信息的结合；
- 引用和数字核验的价值；
- 人工复核在金融场景中的必要性；
- 与工商银行智能研究方向的适配关系。

### 1.4 项目价值主张

| 价值层次 | 解决的问题 | 产品回答 |
|---|---|---|
| 效率层 | 资料搜集、阅读、整理和报告初稿耗时 | 自动解析材料、拆解任务、并行分析和生成草稿 |
| 质量层 | 数字、来源、计算和结论难以复核 | 证据回链、数字核验、质量状态和待复核项 |
| 组织层 | 研究方法依赖个人，成果难以复用 | 统一 Agent 方法、任务历史、权限隔离和知识沉淀 |

## 二 行业背景与项目必要性

### 2.1 数字金融正在从工具数字化进入工作流智能化

金融机构已经广泛建设数字渠道、数据平台和智能化基础设施。随着生成式人工智能和智能体技术发展，金融数字化的重点正在从“把线下流程搬到线上”转向“让系统理解任务、调用知识、组织工具并协助人员完成工作”。

在研究业务中，单点工具只能解决某个环节。例如，搜索工具解决资料发现，文档工具解决内容提取，数据库解决指标查询，写作工具解决文字生成。研究人员仍然需要自己判断资料、安排分析顺序、比对口径、核对来源和合成结论。

因此，下一阶段的数字金融产品需要解决的不只是“有没有一个 AI 工具”，而是：

- 业务任务如何被拆解；
- 数据和知识如何进入任务；
- 多个专业能力如何协同；
- 中间过程如何保存；
- 结果如何验证；
- 人员如何在关键环节接管。

### 2.2 工商银行已经进入金融智能体应用阶段

工商银行 2025 年度报告披露，集团实施“领航AI+”行动，建设“工银智涌”大模型技术体系，构建多模型融合的智能引擎和企业级知识工程体系，并探索多层次智能体协同框架。报告同时披露了投资交易场景中的智能投研助手，为市场洞察、策略研究和投资管理提供辅助。

这说明工商银行的公开发展方向已经涵盖：

- 金融大模型底座；
- 企业知识工程；
- 智能体协同；
- 投资研究辅助；
- 风险防控；
- 全链路安全防护。

弈金的机会不在于重复建设底层模型，而在于面向研究业务提供一个可验证的应用层工作流，将资料、任务、专业分析、证据和人工复核组织起来。

### 2.3 金融人工智能需要同时满足效率与责任

国家金融监督管理总局 2026 年发布的银行业保险业人工智能安全开发应用指导意见提出，金融机构应建立人工智能应用的全生命周期管理体系，完善测评体系、知识工程和人机协同流程，明确系统和数据权限，落实责任追溯，并根据场景重要性和对客影响度实施风险分类分级管理。

对弈金而言，这意味着金融 AI 产品不能只展示模型能力，还必须回答：

- 模型使用了哪些数据；
- 数据是否来源可靠；
- 结论是否可以回到原始材料；
- 输出是否经过人工复核；
- 出错之后是否可以停止、重试或人工替代；
- 不同用户和机构之间是否隔离；
- 哪些内容只能作为草稿，不能直接作为正式金融结论。

### 2.4 项目必要性

弈金的必要性不是因为“市场缺少一个 AI 聊天工具”，而是因为金融研究业务存在以下结构性矛盾：

| 行业矛盾 | 具体表现 | 弈金的切入点 |
|---|---|---|
| 信息增长与人工处理能力有限 | 材料多、来源多、更新快 | 统一材料与公开检索入口 |
| 多维研究与单人串行工作 | 行业、基本面、估值和风险需要同时分析 | Commander 调度 Specialist |
| AI 生成效率与金融可信要求 | 结论流畅但来源、数字和口径可能不清 | 共享引用和质量核验协议 |
| 机构知识积累与个人经验依赖 | 方法难复用，新人上手慢 | Agent 方法论和任务归档 |
| 模型创新与金融责任边界 | 模型可以生成，但不能代替最终判断 | 人工复核、风险提示和权限控制 |

## 三 金融研究业务链条与痛点分析

### 3.1 传统上市公司研究流程

一项完整的上市公司研究通常包含以下步骤：

提出研究问题 → 确定研究范围与资料清单 → 搜集年报、公告、行业资料和公开信息 → 阅读长文档并提取关键事实 → 分析行业和竞争格局 → 分析公司基本面与财务变化 → 补充消息面和政策变化 → 建立估值与情景假设 → 识别风险与不确定事项 → 交叉验证并撰写报告 → 合规复核与人工判断 → 归档和后续更新。

这条链条的难点不在于某一个步骤特别复杂，而在于步骤之间相互依赖：资料选错会影响分析，口径不一致会影响计算，来源缺失会影响复核，前面任务的遗漏会在报告合成阶段集中暴露。

### 3.2 痛点一：资料分散造成研究上下文断裂

研究人员需要在年报、公告、政策、新闻、研报和数据库之间反复切换。不同来源在时间、口径、单位和可信程度上存在差异，研究员必须自行完成筛选、整理和记录。

这会产生三个后果：

1. 搜索和搬运占用大量时间；
2. 资料之间缺乏统一上下文；
3. 后续复核时无法快速回到原始来源。

弈金的产品要求是：上传材料、公开检索、文档分块、关键词检索、页码定位、来源保存和引用回链必须成为同一条流程。

### 3.3 痛点二：专业研究天然需要协作，但工具通常是单线程

行业、基本面、消息面、估值和风险是不同的专业任务。传统研究中，这些任务可能由不同人员负责，也可能由一名研究员依次完成；无论哪种方式，最终都需要重新整理中间结果、统一口径并解决结论冲突。

通用聊天工具往往把复杂任务压缩成一篇回答，无法向用户解释：

- 为什么需要这些分析维度；
- 哪些任务正在进行；
- 哪些结果依赖上游任务；
- 哪些专家结论互相矛盾；
- 哪个结论还缺少证据。

弈金使用 Commander + Specialist 将金融研究中的专业协作显式化。

### 3.4 痛点三：关键数字和结论难以核验

金融研究中的关键数字需要同时满足：

- 数字准确；
- 统计期间明确；
- 单位明确；
- 口径明确；
- 来源明确；
- 计算过程可复现。

只提供一段文字或一个搜索摘要，不能满足这一要求。弈金需要区分原始数据、计算数据和模型判断，并在找不到可靠来源时标记“待核验”，而不是自动补全。

### 3.5 痛点四：研究方法依赖个人，组织知识难沉淀

不同研究员可能使用不同的研究框架和报告结构。优秀研究员的分析方法往往没有被标准化，新人需要通过大量模仿和人工训练才能形成稳定产出。

弈金将行业分析、基本面分析、估值、风险识别、引用核验和报告合成等方法拆成结构化 Specialist 协议，使研究方法可以复用、评测和迭代。

### 3.6 痛点五：AI 提升效率后，新的模型风险同步出现

AI 可能产生：

- 虚构来源；
- 误读表格；
- 混淆时间期间；
- 混淆单位和币种；
- 把预测写成事实；
- 省略风险条件；
- 把不同来源的结论强行合并。

因此，金融 AI 产品的核心竞争力不能只是生成速度，还必须包括结果边界和错误处理能力。弈金将“来源、数字、完整性、逻辑、格式和风险”作为统一质量协议的一部分。

## 四 用户与应用场景

### 4.1 主要用户：银行研究与投研人员

主要用户负责行业研究、上市公司研究、投资分析、市场信息整理或研究报告生产。他们需要快速理解公司和行业，处理大量非结构化材料，获得最新公开信息，形成有证据的初步判断，跟踪报告和任务历史，并在不确定事项上保留人工判断。

弈金替代的是资料搜集、初步整理和报告草拟中的重复劳动，不替代投研人员作出最终投资判断。

### 4.2 次级用户：普通投资爱好者

普通投资爱好者可以使用公开资料研究功能，完成公司公告和年报阅读、行业变化理解、来源查看、风险提示和个人研究笔记整理。

产品边界是：不根据个人资产、风险偏好和收益目标提供个性化买卖指令；报告默认是 AI 生成草稿；最终投资决策由用户自行承担。

### 4.3 扩展用户：科技金融与外部投研机构

科技金融人员可将研究能力延伸到科技型企业、产业链企业和公司客户材料分析，但不能直接用于自动授信审批或自动风险决策。证券公司和基金公司可以使用同一套研究工作流进行行业覆盖、公司研究和研究材料协作。

这些是扩展方向，不改变当前首版围绕上市公司深度研究的产品边界。

## 五 产品方案

### 5.1 产品闭环

| 阶段 | 用户动作 | 系统动作 | 结果 |
|---|---|---|---|
| 创建任务 | 填写公司、问题和范围，上传 PDF | 建立用户、机构、任务和文件关系 | 研究任务与证据集合 |
| 智能规划 | 确认研究目标 | Commander 识别目标，生成任务图 | Agent、输入、输出和依赖关系 |
| 专业执行 | 查看任务进度 | Specialist 并行或按依赖执行 | 行业、基本面、消息面、估值和风险分析 |
| 证据核验 | 点击来源与复核事项 | 保存 URL、标题、定位、获取时间和质量状态 | 可回链证据 |
| 报告合成 | 修改、确认或退回草稿 | Report Synthesizer 处理冲突和失败状态 | 结构化报告草稿 |
| 归档复用 | 查看历史任务与人工修改 | 持久化任务、来源和报告状态 | 可回溯研究资产 |

### 5.2 核心功能

#### 智能研究指挥台

用户用自然语言提出研究问题。Commander 识别公司、研究目标、分析范围和所需专业维度，输出结构化任务图。简单任务可以使用单个 Specialist，复杂任务自动拆分为多个并行任务。

#### 多 Specialist 协作

首版核心角色包括行业分析、基本面分析、消息面分析、估值与财务建模、风险分析和报告合成 Specialist。不以 Agent 数量作为产品卖点。只有当职责、输入、输出和评测标准明显不同时，才新增 Specialist。

#### PDF 材料与公开信息结合

首版正式支持 PDF。系统对材料进行文本提取、分块和关键词检索，并通过公开网页检索补充政策、公告和新闻信息。关键数字不能只依赖普通网页搜索或模型记忆；缺乏可靠证据时必须标记待核验。

#### 实时任务与后台执行

研究任务由后台 Worker 执行，前端通过 SSE 或等效机制展示任务进度。用户刷新页面后可以恢复查看任务状态；失败任务需要记录原因，并支持有限重试、取消或人工接管。

#### 报告合成与人工复核

报告在线以 Markdown 展示，支持 PDF 导出。导出内容包含来源、生成时间、风险提示和人工复核状态。未复核内容必须显示“AI 生成草稿”。

### 5.3 证据与质量协议

每个 Specialist 都遵循“读取任务与证据—生成分析—核验数字、计算和引用—检查完整性、逻辑、格式和风险—输出内容、证据、质量状态和待复核项”的协议。

统一协议包括来源地址、标题、定位信息和获取时间；原始数据、计算数据和模型判断的区分；公式、输入数据和单位的记录；关键数字的来源核验；结论与证据之间的对应关系；失败、超时、冲突和跳过状态；人工复核事项和风险提示。

## 六 工商银行数字金融适配

### 6.1 与工商银行公开方向的关系

工商银行公开材料显示，其已经围绕“工银智涌”建设金融大模型技术体系，推进企业知识工程和多层次智能体协同，并在投资交易场景建设智能投研助手。

弈金的角色是研究业务应用层候选方案：

- 不替代工商银行底层模型；
- 不宣称已经接入工商银行内部系统；
- 不使用工商银行非公开数据；
- 不宣称获得工商银行授权；
- 通过开放接口和 Provider 抽象预留未来适配空间。

### 6.2 智能投研场景

弈金可辅助研究人员完成上市公司和行业材料的资料整理、问题拆解、初步分析和报告草稿。研究人员仍然负责研究假设、关键判断、事实复核和最终发布。

### 6.3 企业知识工程场景

弈金把用户上传材料、公开来源、任务过程、Agent 输出和人工修改组织为有关系的研究资产。未来可以与机构知识库、专业 RAG 库和内部研究方法结合，形成可更新、可共享的知识工程入口。

### 6.4 金融安全场景

弈金把权限隔离、来源回链、数字核验、人工复核、风险提示和任务审计作为默认能力。对于直接影响客户利益、资金交易、授信审批或正式投资决策的高风险场景，系统只能作为辅助工具，必须经过机构准入、测评和人工监督。

## 七 技术架构与创新点

### 7.1 总体架构

Web 前端包括任务与文件界面、实时进度界面、报告与引用界面、人工复核与导出界面。API 层负责认证、权限、文件、任务、Agent、工作流和 SSE 订阅。任务编排层负责 Commander、DAG 调度、Specialist 执行和报告合成。质量与证据层负责 PDF 解析、检索、引用核验、计算核验和报告审查。PostgreSQL、Redis、Worker 和对象存储抽象提供持久化、队列和文件保存能力。

### 7.2 Provider 解耦

LLM Provider 负责模型调用、流式输出、结构化输出、超时、重试、错误分类、Token 统计和能力声明。Search Provider 独立负责联网搜索、公开文件检索、来源保存、去重和获取时间记录。

Agent、DAG 调度器和报告层不直接调用具体模型 SDK。这样可以在不修改 Agent 编排逻辑的情况下替换模型，也能把模型能力和金融检索能力分开管理。

### 7.3 项目创新点

#### 研究流程创新

将金融研究中的专业分工建模为 Commander + Specialist，使复杂研究任务可以拆分、并行和按依赖执行。

#### 证据链创新

将来源追溯、过程追溯和任务追溯统一起来，使用户可以从报告回到 Agent 输出、从 Agent 输出回到来源和材料定位。

#### 金融知识工程创新

将行业分析、基本面、估值、风险识别和报告合成中的方法和质量要求编码为可复用的 Agent 协议，而不是依赖用户临时编写提示词。

#### 安全治理创新

将人工复核、风险提示、待核验状态、权限隔离和失败接管写入产品流程，不把安全作为部署完成后的附加功能。

## 八 竞品与替代方案分析

| 对比维度 | 通用对话式 AI | 传统金融终端 | 低代码 Agent 平台 | 弈金 |
|---|---|---|---|---|
| 主要价值 | 通用问答与写作 | 数据查询与专业终端 | 自定义搭建 Agent | 金融研究工作流 |
| 研究分工 | 通常是一问一答 | 依赖人工组织 | 需要用户自行配置 | Commander 自动拆解 |
| 材料处理 | 能力和格式不稳定 | 依赖已有数据和库 | 取决于配置 | PDF 上传、检索和引用 |
| 证据能力 | 来源不稳定 | 数据较强但过程不一定沉淀 | 取决于配置 | 来源、任务和过程统一留痕 |
| 人工复核 | 需要用户自行完成 | 由机构流程完成 | 需要自行设计 | 产品内置复核状态和待复核项 |
| 部署方式 | 平台依赖较强 | 机构采购和部署 | 工程配置成本较高 | SaaS 与 Docker 私有化方向 |
| 主要空白 | 不懂机构工作流 | 不负责智能协同 | 不提供开箱即用金融方法 | 连接模型、材料、知识和业务人员 |

弈金不与传统金融数据库正面竞争，也不试图替代大型金融机构的底层模型。其定位是数据与模型之上的应用层编排和研究协作层。

## 九 当前实现、验证证据与后续规划

### 9.1 当前 MVP

当前项目已经具备 Commander + Specialist 编排、Agent 注册和提示词管理、SSE 实时流式输出、DeepSeek 联网搜索、搜索引用持久化和展示、用户注册登录、任务历史、Web 工作台、Docker Compose 一键部署以及 Markdown 报告展示和 PDF 导出方向。

### 9.2 当前边界

当前版本仍存在边界：

- 结构化财务数据接口尚未纳入正式首版；
- 复杂表格抽取和 OCR 不属于当前首版；
- Specialist 之间的完整链式依赖仍需继续完善；
- 后端自动化测试、权限测试和评测集需要补齐；
- 市场效率、用户满意度和商业转化指标尚未经过真实从业者长期验证。

项目不把“节省多少时间”写成已经验证的事实，而将其作为后续评测目标。

### 9.3 后续路线

| 阶段 | 重点任务 | 目标 |
|---|---|---|
| 阶段一 | 上市公司研究 MVP | 跑通上传、检索、编排、核验、报告和人工复核 |
| 阶段二 | 可靠性增强 | 完善 DAG、重试、取消、恢复、质量检查和权限隔离 |
| 阶段三 | 数据与评测 | 接入公开结构化数据，建立 10—20 家 A 股公司标准评测集 |
| 阶段四 | 金融机构试点 | 私有化部署、安全评估、业务适配和人工反馈闭环 |
| 阶段五 | 场景扩展 | 扩展科技金融企业研究和机构研究协作，不盲目增加 Agent |

## 十 评测体系与验收指标

### 10.1 任务拆解评测

评估 Commander 是否识别正确公司和研究目标，选择合法且必要的 Specialist，生成完整的输入和输出字段，正确表达并行关系和依赖关系，并在简单任务中避免无必要的多 Agent 调度。

### 10.2 事实、数字与引用评测

目标指标包括：

- 关键数字可追溯率：目标 100%；
- 引用覆盖率：目标不低于 90%；
- 结构化输出成功率：目标不低于 95%；
- 找不到可靠来源时的待核验标记率：目标 100%。

### 10.3 工程可靠性评测

评估任务成功率、失败原因记录完整度、有限重试、任务取消、断线恢复、越权读取防护、在线报告与导出报告一致性。

### 10.4 人工价值评测

记录单次任务耗时、人工修改段落数量、人工补充来源数量、人工发现的数字错误数量、研究员对可读性和可核验性的评价，以及哪些步骤仍然需要人工判断。

## 十一 风险分析与合规边界

### 11.1 模型幻觉和引用失真

控制措施包括强制引用、关键数字核验、来源不可用时标记待核验、报告导出前人工复核、保存任务过程和失败状态。

### 11.2 数据安全与权限风险

控制措施包括任务、文件和报告绑定用户与机构；文件内容不能跨用户或跨机构返回；API Key、JWT 密钥和数据库密码只通过环境变量注入；敏感信息不得写入普通日志；外部搜索和模型调用经过 Provider 边界。

### 11.3 金融误用风险

弈金不自动执行交易，不生成个性化买卖指令，不把 AI 草稿自动发布为正式金融结论。普通投资爱好者只能使用公开资料研究辅助；机构场景下，涉及投资决策、资产评估、授信审批和其他高风险业务时，必须经过机构准入、测评和人工监督。

### 11.4 工商银行场景误读风险

项目只使用工商银行公开披露的战略和技术方向进行适配分析。任何正式接入、试点、数据使用、模型调用和系统部署，都必须另行获得授权并完成安全评估。本文不代表工商银行官方立项、授权、合作或背书。

## 十二 项目实施与资源规划

### 12.1 团队协作

项目至少需要覆盖产品与金融场景、后端与任务编排、前端与交互、数据评测与安全等职责。在学生团队资源有限的情况下，优先保证上市公司研究闭环，不同时展开理赔、财富管理、AML、自动交易等多个业务域。

### 12.2 资源投入原则

校赛阶段优先使用公开材料和公开数据源，以验证产品闭环。进入机构试点后，再根据数据等级、并发量、部署环境、安全测试和模型准入要求形成正式预算。

不在项目早期用未经验证的市场规模、收益预测或客户数量替代产品可行性证明。

## 十三 结论

弈金选择的不是“再做一个 AI 聊天机器人”，而是一个清晰的数字金融应用问题：如何把金融研究从个人依赖、资料分散、串行执行和难以复核的工作方式，升级为任务可编排、证据可追溯、过程可审计、知识可沉淀的智能研究工作台。

项目以工商银行内部研究和投研人员为主要用户，以上市公司深度研究为首个核心场景，普通投资爱好者和外部投研机构作为不同层级的扩展用户。它既能承接工商银行公开发展的智能投研、企业知识工程和智能体协同方向，又保留当前项目已有的 PDF、公开检索、Agent 编排、引用展示和报告生成能力。

项目的最终价值不在于让 AI 代替人作出金融判断，而在于让 AI 负责资料组织、任务执行和研究初稿，让专业人员把时间集中到判断、复核和责任承担上。
